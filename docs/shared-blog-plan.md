# 双人共同管理博客：实施方案

状态更新（2026-10-27）：用户已确认采用“公开网站代码 + 私有 Markdown 内容仓库 + 构建时读取”的架构。内容库为 sakarijoy/blog-content，网站通过只读部署密钥获取已发布内容。配置与日常流程见 [私有内容说明](private-content.md)。当前可使用 GitHub 网页编辑器写作；独立后台与 OAuth 登录尚未上线，第二位用户名仍待提供。NAS 接入继续暂停。

下文 Supabase 结构是早期备选草案，没有创建对应云端项目。后续后台优先围绕现有私有内容库开发，只有另行确认迁移需求时才采用数据库方案。

## 已确认需求

- 两人是共同管理员，共同维护整个博客，而不只是分别写文章。
- 两人都能新增、编辑、发布和下架文章、旅行记录与视频，管理图片/封面以及审核评论。
- 两人管理的是同一个内容库。系统记录创建者、最后修改者和更新时间；不限制只能修改自己上传的内容。
- 第二位管理员有 GitHub 账号，用户名尚待提供；现在不创建虚构账号或开放任意用户的管理权限。
- 访客可浏览公开内容，不需要 GitHub 账号即可留言。

## 建议架构

保留现有页面外观，前端可继续部署到 GitHub Pages；统一后端建议使用 Supabase：

- Auth：两个独立 GitHub 登录账号。
- Postgres 数据库：文章正文、视频介绍、旅行记录、站点资料、管理员成员和评论。
- Storage：视频文件、封面和文章图片；大文件使用断点续传。
- Edge Function：接受访客评论，验证输入和防刷验证，写入待审核评论。
- 网站的 /admin/：统一编辑与媒体管理后台。

文章与页面模板彻底分离，正文保存为数据库字段（例如 Markdown）。模板只负责展示，不再手写每篇文章的 HTML，也不需要每发布一次内容都提交前端代码。

此方案包含需要开发的网站管理后台；Supabase 控制台不是两位作者日常写作的界面。

## 权限

| 操作 | 管理员 A | 管理员 B | 普通访客 |
| --- | --- | --- | --- |
| 浏览已发布内容 | 可以 | 可以 | 可以 |
| 新建、编辑、发布、下架全部内容 | 可以 | 可以 | 不可以 |
| 上传和管理视频、图片 | 可以 | 可以 | 不可以 |
| 查看草稿及未公开素材 | 可以 | 可以 | 不可以 |
| 提交评论 | 可以 | 可以 | 可以，无需 GitHub |
| 审核、隐藏评论 | 可以 | 可以 | 不可以 |
| 修改站点名称、简介、导航等 | 可以 | 可以 | 不可以 |

管理员资格由后端成员表与数据库/存储权限规则校验，不能仅依靠隐藏按钮，也不能让任意 GitHub 登录用户自动成为管理员。初次成员配置需通过可信控制台完成，前端不能自行提升权限。

## 数据结构草案

- blog_members：Auth 用户 ID、管理员角色、显示名。初始只添加核实过的账号。
- content：文章/旅行/视频类型、唯一地址、标题、摘要、正文、封面、作者、草稿/已发布/已下架状态、创建者、最后修改者、版本号、发布时间。
- media：文件路径、类型、大小、关联内容、上传者、上传状态。
- comments：关联内容、昵称、可选联系邮箱、正文、待审核/已通过/已隐藏状态。
- site_settings：博客名称、共同简介、首页介绍、栏目设置。

公开评论查询只能返回通过审核的评论和公开展示字段，不能返回留言邮箱或后台审核信息。访客提交经服务端校验后进入待审核状态，不能指定审核通过。

媒体区分草稿和已发布资源，草稿上传到私有存储。正式访问方式需根据发布流程配置，避免仅隐藏草稿页面却公开了草稿文件。

## 视频上传

第一阶段支持浏览器上传、进度、断点续传、封面、简介、发布状态和网页播放器。

文件存储不等于专业视频点播。自动转码、多清晰度、HLS、超长视频等需求需额外评估视频点播服务。单文件大小、总容量与播放流量按所选云服务套餐核实后设置，暂不承诺具体额度或费用。

## 两人共有的两个层面

1. 博客应用：两人具有同等内容管理权限，分别登录，不共享密码。
2. 基础设施：如代码仓库、后端项目、账单与域名也要求共同掌握，应单独配置协作/所有者权限。GitHub 个人仓库的协作者不等同于共同所有者；可考虑组织仓库，但迁移可能影响默认 Pages 地址，实施时须另行检查。

## 实施顺序

1. 确认后端服务、视频文件的大致大小与数量，以及是否需要专业转码。
2. 创建后端项目，准备数据库、存储和权限规则；先录入已核实的第一个管理员。
3. 配置 GitHub OAuth 与正确的回调地址；客户端密钥仅保存在后端服务中。
4. 开发统一后台：内容、媒体、评论审核与站点资料。
5. 将现有文章迁入数据库，页面改为读取内容；验证草稿不可公开访问。
6. 接入无需 GitHub 的评论提交与审核。
7. 用实际视频测试上传、续传、播放与访问权限。
8. 第二位账号确认后，核实其身份并授予与第一个管理员相同的博客权限。
9. 验证两位管理员的完整流程后再发布前端。
